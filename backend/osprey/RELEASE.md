# Osprey VM2 release

Osprey is an independent scanner consumer of Pallas option snapshots and matching completed cash candles. It uses the existing Rusty volume archive and uses same-cut Rusty sector classifications when available. The fallback is Osprey breadth. It consumes the existing NSE regular-session calendar. No new broker collection, raw archive download, live DuckDB read, or order execution is required.

Deployment changes are the Osprey Python engine and publisher, sector mapping, isolated systemd service and frontend sidebar/API/page. Aurum and Kairos services continue to run. Osprey publishes one gzip/base64 snapshot and one small cut index per five-minute interval. ORDS reads use both source and session date. The VM2 ORDS endpoint ignores cut, limit, and offset parameters, so exact snapshot reads use per-cut sources. The document bound is 96 KiB compressed envelope and 512 KiB expanded rows. One open tab makes at most 12 automatic API requests per market hour. The latest API reads one bounded index and one cut, with private cache policies and sharing. Explicit historical selections use one exact-cut read with caching.

Preflight used eight retained Nov 13 cuts on VM2. The 09:50 result was 498 mode rows and 25,681 bytes at the ORDS origin. Peak process RSS was 70,140 KiB. Initial MemAvailable was 462 MiB and there was no observed ongoing swap I/O in the two one-second spot samples. The unit uses MemoryHigh=100M, MemoryMax=144M, Nice=15 and CPUQuota=15%. The scanner processes only the existing current-day captures and commits its checkpoint and outbox in one local SQLite transaction. Retries reconcile uncertain writes against exact source/date/ID. An index is published only after its snapshot is acknowledged.

Rollback on VM2 uses sudo systemctl disable --now osprey.service. Keep the Osprey state and source captures. Frontend rollback reverts only the release commit. An existing unit or directory is treated as a separate upgrade requiring a timestamped backup before modifications.
