# Kairos 2.0 paper trader

Own VM2 unit `/etc/systemd/system/kairos2.service`; code and private state `/home/ubuntu/kairos2`. Uses existing Ocelot Python/httpx, credentials, universe and ORDS configuration. No additional database, full-chain feed, training, live DuckDB access or broker order endpoint. Existing VM1 Kairos is retained. User approved paper trades, first confirmed AI >=70, otherwise no trade.

Consumes confirmed, non-recovered Pallas files issued after worker startup on the current IST date. Requires the reviewed frozen model ID, valid score and scored timestamp, age <=90 seconds, verified NSE opening/closing schedule, and entry before 11:30. Orders eligible events by original issue instant; scores break ties at the same instant. No historical CSV import or full-day fallback. Contract must match the signal's exact underlying/expiry/strike/leg. Wrong expiry, unavailable current mapping and missing/invalid data suppress entry.

Accepted Pallas model for Engines 1/2: `pallas-revpole-lgb-d53e5a653f19`. From October 7, 2026, also accepts Engine 3 model `pallas-pdh-lgb-20261006`, restricted to `pallas_pdh_break_ai`, bullish `PDH_BREAK_FLAG` and a valid prior R1 crossed at the saved breakout spot (`Breakout_Spot >= Prior_OI_Line`). Missing/invalid/wrong-type lines or OI cross N suppress only Engine 3 entries. A reported boolean alone cannot override the saved price comparison. Engines 1/2 keep their existing eligibility without an OI-cross requirement. The frontend OI filter remains independent.

From October 8, 2026 (`pallas-e3-queue-exhaustion-20261008`):
1. **Exhaustion Gate:** Pole moves >3.5% are rejected across all setups to prevent climax exhaustion traps (e.g., chasing stocks already down 5% in opening bars).
2. **Early Deferral:** Before 10:00 AM (cuts <=09:55), lower-tier setups (Reverse Pole / Late Pole) require AI >=80 to prevent burning the daily slot on opening noise.
3. **Pattern Priority:** Within candidate rankings, setups are prioritized by structural pattern tier (`PDH_BREAK_FLAG` > `STANDARD`/`CASCADE` > `REVERSE_POLE`) and AI score before issue arrival order.
4. **Single-Lot Buffer:** `buy_size()` permits 1 whole minimum lot up to Rs 35,000 when high-ticket options slightly exceed the standard Rs 30,000 multi-lot budget.

AI >=0.70, one paper trade per day, budget, freshness, stops and accounting rules remain unchanged. Previous-model signals do not qualify for new entries; saved trades retain their original model, position and daily lock. A later model replacement requires an explicit pin update and validation. Health publishes both accepted model IDs and the Engine 3-only OI gate; entry records preserve submodel and compared spot/line. Policy changes trigger a fresh health publication without resetting trade state.

Resolves real lot sizes with Upstox option contracts. Up to five quoted ask levels size whole lots within Rs30,000, respecting minimum lot and actual depth; untradeable events are logged SKIP. Paper fills use weighted quoted ask/bid depth, require matching instrument, current-session last trade, nonfuture snapshot/receipt time, snapshot <=30s and receipt <=10s old. They are simulations, not guaranteed executions. Quotes are polled every five seconds for one open position; entry retries every five seconds, with broker rate limit of at most two requests/second and 60-second 429 cooldown. No LTP fallback when depth is missing.

Initial premium stop -15%; observed bid peak +15/+25/+40/+60/+100% moves stop to +2/+15/+25/+40/+70%. Stop updates persist on each quote; exits execute in the simulation at observed bid depth, not at an ideal stop threshold. Exit at 11:30 IST or an earlier market close. Missing exit quotes retain the position and show pending status; midnight does not invent a closing fill. Gross bid/ask PnL excludes brokerage/taxes. A new trading date cannot enter while an overdue position remains open.

Atomic state commits positions, trailing values, consumed signal IDs, one-entry/day flag and publication outbox together. Advisory lock prevents duplicate processes. Restart recovers the position and uncertain publication; it never retrospectively buys already-issued events. ORDS source `kairos2`, cap `KAIROS2`, mode `paper`, stable Doc_ID, ENTRY/MTM/EXIT/SKIP/HEALTH. Before each uncertain/retried publication, read the same date/source and suppress a matching Doc_ID. Marks every 30 seconds; health every 60 seconds during monitoring and 15 minutes outside it. Outage mark/health backlog capped at 1000; entry/exit persistence remains enabled.

`/kairos` defaults to Kairos 2.0, with Classic selector preserving the old bot. Engine PnL is isolated, IDs include source, new accounting fields survive shared API normalization. Date selection, login and auto-refresh retained. The AI dashboard shows the actual selected score, entry/mark/stop, quantity/lots, budget, execution timeline and history; Kairos is third in navigation. Health distinguishes empty session from missing/overdue worker heartbeat. The worker itself does not send Telegram; the separate [notification relay](../telegram_alerts/README.md) alerts fresh paper ENTRY/EXIT events alongside confirmed Pallas AI>70 signals.

Tests: `python -m unittest test_kairos2 test_transport` locally; frontend `node scripts/test-kairos2.mjs`, focused ESLint and production build. `kairos2_live.py --probe` is read-only broker/ORDS connectivity and never creates trades/state. Native inference/training dependencies are not installed. Service MemoryHigh64M, MemoryMax96M, CPUQuota15%, Nice15, no new listener. Measure during actual session; premarket checks cannot certify fills or full-session reliability.

Rollback: `sudo systemctl disable --now kairos2.service` only. Preserve state and backups. Restore the prior frontend files/commit using normal Git/Vercel deployment. Never delete paper state, restart Pallas/Ocelot/old Kairos or change their modes as part of rollback.

API schemas verified against official [full quotes](https://upstox.com/developer/api-documentation/get-full-market-quote/), [option contracts](https://upstox.com/developer/api-documentation/get-option-contracts/) and [market timings](https://upstox.com/developer/api-documentation/get-market-timings/). Variable fractional ISO timestamps are normalized for VM Python 3.10; Unix millisecond timestamps are converted to seconds.
