# Lupus live rules and historical replay

Lupus consumes the exact current Rusty CE/PE values and completed cash candles through a small local Ocelot adapter. It does not place orders, subscribe to a feed, call a broker or open the live DuckDB. A separate stdlib worker publishes source `lupus`; `lupus_health` is separate and cannot replace the last board.

Bull: a failed-above historical OI level from the prior five sessions (wall known before failure; historical rise >=0.25%, subsequent fall >=0.5%, failure close below). Observe an actual completed-candle reclaim, then require close above the line and recorded PDH, positive move from open and negative CE. Choose the highest reclaimed line per symbol. Rank CE ascending first; apply CE<=-3% afterward without refilling rejected ranks. PE unrestricted.

Bear: a preceding-five-session OI line and a later historical wick/close failure, both strictly prior to today. Retain expired historical lines. Current completed close below line and session open, CE>0 and rising versus exactly five minutes earlier. Nearest qualifying line; rank price weakness descending. Through15:00. Ties use minimum rank on both sides; Top3 can contain ties.

The preview folder, all eleven session JSONs and AI study are included under protected `/lupus-preview`. `/lupus` offers Live and Historical replay. AI study and future outcomes remain historical-only. Live CE values are published Rusty values; some replay bear inputs were reconstructed and can differ from the published series. Historical parity is not a profitability or live-result guarantee. Revised historical cash used for initial context is disclosed by the seed manifest.

Initial context is locally built through2026-10-16. Subsequent history is updated after16:00 from Ocelot's EXISTING end-of-day candle request responses, before its OB archive truncation. No extra API request is made. Same-day15:25 captured chains reuse installed chart_oi.build_levels for wall definitions. Require full75-bar cash sessions and >=90%complete cash coverage. Missing or degraded EOD inputs keep context unchanged and report an error. Only twelve sessions of derived working context are retained; original source archives/inputs are not deleted.

One process lock, atomic state and durable outbox, stable IDs with bounded publication read-back. Duplicate inputs never revise a recorded decision. Missed captures recovered later are explicitly marked and issued at actual processing time. Future/wrong-date/late Rusty inputs are rejected. Missing exact completed candles suppress the cut and retain the last successful board with health ERROR. The current API consumer polls once/minute while visible during regular hours, slowly outside weekday hours, once on weekends; replay loads dates only on selection. All data and assets remain authenticated and browser-private.
