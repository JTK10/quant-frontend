# KAIROS9 paper parallel worker

This worker is independent of Classic and Kairos2. It has no broker order path and consumes existing Irbis state and atomic Pallas/Ocelot captures. The only broker request is a bounded GET for exact contract metadata after selection. Captured measured bid/ask and displayed depth are required; missing, stale, degraded, oversize, or ambiguous inputs fail closed.

The frozen LightGBM selection models were trained locally through 2026-10-13. Inference uses the standard library and is forbidden on training dates. Model lineage contains hashes of the local source datasets. Synthetic parity vectors verify classifier/regressor inference against LightGBM. Upstream feature provenance is not independently certified; spread feature remains the documented 1.8% imputation for training parity, separate from measured execution quotes. Exit ML remains disabled.

The existing earliest-eligible selection rules are retained. One candidate/day, exact T+5 five-minute capture (not a tick or candle-open fill), observed ask paper entry, observed bid marks/exits, verified integer lots and Rs35,000 premium budget; fees are additional. Displayed depth must cover quantity. No claim of achieved market execution, queue priority, slippage protection or intrabar stop protection is made. Two-bar confirmation requires consecutive five-minute captures. Missing exit quotes retain the position for review, including across session boundaries.

All durable state, lock and outbox files are isolated under /home/ubuntu/kairos9. Saves are atomic with fsync. ORDS documents use source kairos9 and stable source/date/identity IDs. A durable intent precedes POST. An uncertain POST is checked by read-back; absent confirmation it is never blindly retried and requires manual review. Outbox is capped at 128 and new entries stop at 100. Health publication is at most one per 15 minutes, independent of the board. Local checks run every 15 seconds and health writes every 60 seconds. Option/cash sources retain existing five-minute cadence. There are no new tick subscriptions or live database readers.

The exporter adds a separate quotes dictionary, leaving the six-column chains and existing retention code unchanged. Ocelot must reload that module; restart only its named unit in the premarket window. Classic, Kairos2, Pallas and Irbis are not restarted. Frontend uses a separate Kairos9 tab and existing authenticated source-filtered API. Scanner refresh is 60 seconds; chart OI cadence is unchanged. Charts share one existing stream per URL/tab, pause while hidden, read historical snapshots once, and coalesce painting to at most four times/second while retaining both candles at a boundary.

Measured representative workload: 11 archived feature cuts, approximately 7.6 CPU seconds total and 39 MB peak RSS. The archived workload bypasses the training-date gate in memory only, with no broker/publication calls. Unit memory limits are 48 MB high/72 MB max and CPU quota 15%, Nice 15; VM2 historical Ocelot peak was approximately 400 MB. No scientific runtime is installed on either VM.

Tests: `python -m unittest test_kairos9` in this folder. Training/backtesting remains local. `benchmark.py` is read-only and uses bounded archived captures. Service startup is `kairos9_live.py`; never use the research walk-forward runner as a service.


October 14 incident correction: broker metadata now uses the existing Ocelot/Kairos2 HTTPX runtime; the previous urllib client reproduced HTTP403 while the same token/contract succeeded through HTTPX. Daily entry is consumed only when a paper ENTRY is recorded. Transient metadata failures retry at most three times within the current cut deadline (30/60 seconds, 60 seconds for429); terminal failures skip that cut while preserving later eligibility. Missing T+5 captures are never retrospectively filled. Integer sizing is bounded by premium budget AND current displayed bid/ask depth. Decision/failure audit survives closed-session status and is archived at day rollover. Legacy daily locks are not silently cleared. Broker requests remain GET-only; no orders or new market feeds.
